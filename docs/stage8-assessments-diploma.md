# Этап 8 — экзамены, проект и диплом

21.09.2026. Собран основной демонстрационный учебный цикл: изучение материалов → экзамены по темам → итоговый проект → подтверждение имени → подготовка и скачивание PNG-образца. Реальное оценивание, загрузка файлов и персональная выдача диплома не подключены.

## Проверить вручную

Из `frontend` запустить `npm run dev:mock`. Открыть http://localhost:3000 и войти как `student@example.test`, пароль `Repeat123`.

1. Создать и утвердить программу. В первой теме отметить изучение обоих обязательных материалов.
2. Нажать «Открыть экзамен», прочитать условия и начать попытку.
3. Ответы сохраняются автоматически через 650 мс после изменения, при переходе между вопросами и кнопкой «Сохранить сейчас». До подтверждения API показывается несохранённое состояние.
4. Нажать «Сдать экзамен». Диалог предупреждает о необратимости сдачи и количестве пропусков. После подтверждения сначала показывается отправка, затем проверка, затем результат. Обновление страницы не создаёт новую попытку.
5. Для успешного прохождения **демонстрационных** вопросов выбрать «Получение итогового статуса проверки», затем «Проверить требования» и «Проверить сохранение ответов», ввести «пример» и развёрнутый ответ от 20 символов. Это проверка интерфейса, а не реальные задания курса или AI-оценка.
6. После результата `passed` открывается следующая тема. Повторить цикл для трёх тем.
7. Открыть итоговый проект. Заполнить описание от 30 символов и при необходимости HTTP/HTTPS ссылку, сохранить и отправить на проверку. В тестовом режиме описание нужной длины даёт успешный результат; реальная оценка по критериям отсутствует.
8. Перейти к диплому, подтвердить имя. Заявка восстанавливается после reload. Готовый экран позволяет скачать **незаполненный PNG-образец Figma**. Имя сохраняется в данных заявки, но не добавляется в изображение. Это не персональный диплом.

## Структура

| Маршрут | Реализация |
| --- | --- |
| `/app/tracks/:id/exam/:topic` | `pages/exam/ExamPage` — условия, runner, проверка и результат |
| `/app/tracks/:id/project` | `pages/project/ProjectPage` — отдельная форма на общем механизме попыток |
| `/app/tracks/:id/diploma` | `pages/diploma/DiplomaPage` — доступ, имя, ожидание и образец |
| `/app/diplomas` | `pages/diploma/DiplomaIndex` — переход к статусу по активным курсам |

`features/assessments` содержит схемы, HTTP-адаптеры и ключи кеша; `features/diplomas` — отдельную модель выпуска. `ExamQuestion` — UI-организм с single/multiple/short/free формами без API и без оценивания. Результат и права определяют mock handlers, а не страницы. Данные тестового оценивания находятся только в `mocks` и не включаются в production-сервис.

Автосохранение не скрывает ошибки: при сбое текст остаётся в форме, доступен ручной повтор. При 409 автоматическое сохранение останавливается; загрузка сохранённой попытки явно заменяет черновик. Уход с несохранённой работой требует подтверждения. Enter в текстовом ответе не сдаёт экзамен.

## Предварительный API

Эти пути — изолированный preview-контракт, **не endpoint реального backend**. Адаптеры запрещают их вне mock-режима.

| Метод | Путь и назначение |
| --- | --- |
| GET | `/__preview/tracks/:id/assessments/:kind/:target` — условия, доступ, последняя попытка, краткая история |
| POST | Тот же путь, `{ action: "start" }` — начать или восстановить активную попытку |
| POST | `{ action: "save", attemptId, expectedVersion, answers, project }` — сохранить всю текущую форму |
| POST | `{ action: "submit", attemptId, expectedVersion, allowUnanswered }` — закрыть редактирование и начать проверку |
| GET | `/__preview/tracks/:id/diploma` — locked/eligible/generating/ready и данные заявки |
| POST | Тот же путь, `{ name }` — зафиксировать имя и создать одну заявку |

`kind=exam`, `target=topicId`; для проекта `kind=project`, `target=final`. У мутаций обязателен `Idempotency-Key`. Повтор того же ключа с другим payload отклоняется; повтор потерянного ответа возвращает существующий ресурс. Сохраняется не более одной активной попытки для одной проверки. Повтор после `passed` или `review_required` не создаёт новую попытку.

Попытка: `id`, `version`, `planVersion`, `status`, `questions`, `answers`, `project`, `dueAt`, `feedback`. Состояния: `active`, `submitted`, `evaluating`, `passed`, `failed`, `review_required`, `expired`. После сдачи ответы неизменяемы. Неоднозначный результат ничего не разблокирует. При смене версии программы результат требует дополнительной проверки.

В preview нет таймера по умолчанию. Если API возвращает `dueAt`, UI вычисляет остаток из абсолютного срока; mock-сервер отдельно запрещает сохранение и сдачу после истечения. При подключении backend нужно согласовать серверное время/смещение клиентских часов. Проверка опрашивается раз в секунду только в промежуточных состояниях, без фиктивного процента выполнения.

Успех экзамена переводит тему в `passed` и открывает только следующую тему. Итоговый проект доступен после всех тем, заявка на диплом — после успешного проекта той же версии программы. Учебный прогресс материалов остаётся отдельной метрикой. Тестовое хранение — `sessionStorage`, отдельно по пользователю; это не долговременное серверное хранение.

## Сценарии ошибок

- `sessionStorage['repeat-preview-assessment-response'] = 'start' | 'save' | 'submit'` — потерять следующий ответ после сохранения; повтор не создаёт дубликат.
- Значение `offline-save` — отказ до сохранения; черновик остаётся в форме.
- `repeat-preview-assessment-outcome = 'failed' | 'review_required'` — одноразовый итог следующей проверки.
- `repeat-preview-diploma-response = 'lost'` — потерять ответ после создания заявки; повтор возвращает её.
- Для deadline/version QA фикстура хранится в `repeat-preview-assessments:<identity>`. Эти переключатели доступны только в тестовой среде.

## Что остаётся открытым

- Исторический локальный backend имеет `/exams/:id`, `/exam-attempts/:id`, `If-Match` для отдельных ответов и сертификаты с jobs/download-links. Наш временный контракт требует отдельного адаптера, а не замены base URL. Полноценный проектный API в этом снимке не найден.
- Последний исследованный remote `de08e1d420239bc63bdded2355e29418e926c5f2` содержит gitlink без `.gitmodules`; актуальный адрес API от пользователя пока не получен. Корневой backend не менялся.
- Реальные exam/knowledge/rubric версии, задания, критерии и AI-оценивание требуют серверного контракта. В текущем preview фиксируется `planVersion`; не имитируем существование остальных версий.
- Файлы проекта, загрузка/проверка вложений, персональный рендер диплома, временные download URL и их обновление не реализованы без API.
- История показывает статусы попыток; подробный просмотр любой старой попытки, пересмотр неоднозначной оценки, обновление активной попытки при смене программы и полный разбор по рубрике остаются отдельными задачами.
- Раздел дипломов сейчас показывает статусы активных курсов; полноценный архив выданных документов ожидает `/certificates`.
- Физические устройства, VoiceOver/NVDA и реальный backend не проверены.

Результаты автоматических проверок — в [матрице совместимости](compatibility-matrix.md). Следующий основной этап — 9: настройки, тарифы и публичная часть. Интеграционные ограничения этапа 8 остаются открытыми.
