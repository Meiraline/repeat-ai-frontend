# Этап 7 — AI-репетитор

21.09.2026. Реализован основной frontend-сценарий на mock API: отдельные диалоги курса, история, контекст, отправка и восстановление ответа. Реальный AI не подключён.

## Как проверить

Из `frontend` запустить `npm run dev:mock`, открыть http://localhost:3000. Тестовый вход: `student@example.test`, пароль `Repeat123` (без точки).

1. Создать и утвердить курс либо открыть уже созданный в этой вкладке.
2. На карте или в уроке нажать «Спросить репетитора». Также доступен раздел «AI-репетитор» в меню с выбором курса.
3. Выбрать весь курс или доступную тему и нажать «Новый диалог».
4. Ввести сообщение. Enter добавляет строку; отправка выполняется кнопкой. Текст ограничен 8000 символами.
5. Ответ явно обозначен демонстрационным. Перезагрузка восстанавливает историю; другой диалог имеет собственные сообщения.

Контекст курса и темы показан над чатом и рядом с полем. Изменение версии программы требует явного подтверждения перед следующей отправкой. Старые сообщения сохраняют прежнюю версию. Неотправленный текст защищён предупреждением при уходе, но не сохраняется после подтверждённого ухода или закрытия вкладки.

## Реализация

| Область | Путь |
| --- | --- |
| Выбор курса | `/app/tutor`, `pages/tutor/TutorIndex` |
| Диалоги курса | `/app/tracks/:id/tutor?thread=…`, `pages/tutor/TutorPage` |
| Логика и схемы | `features/tutor` |
| Сообщение и источники | `components/molecules/TutorMessage` |
| Безопасный контент | Существующий `components/organisms/LearningContent` |
| Preview-сервер | `mocks/handlers/tutor.ts` |

Кеш привязан к сессии, треку и версии программы: `['session', 'tutor', trackId, version]`. При смене версии предыдущая проекция остаётся на экране до загрузки новой, чтобы не потерять черновик. Выбранный thread хранится в URL. Чат не переносит тему незаметно между диалогами. Из урока тема подставляется в форму создания; существующий диалог самовольно не меняется.

Восстановление полного ответа использует тот же `clientMessageId` и `Idempotency-Key`. Повтор после потерянного ответа возвращает историю без второго сообщения. Частичный ответ сохраняется как `partial`; «Восстановить ответ» заменяет только этот ответ, сохраняя пользовательское сообщение. Частичный ответ старой версии остаётся историческим после подтверждения нового контекста.

Клиент не отправляет сырые HTML-фрагменты в DOM. Источники отображаются только из ответа API, ссылки проверяются общим `safeSourceUrl`. Демонстрационные ответы не содержат выдуманных ссылок и явно сообщают, что источники не использовались.

В ходе проверки исправлена общая очистка сессии: `forget()` сохраняет наблюдаемый query профиля и устанавливает `null`, удаляя остальные query. Прежний `client.clear()` удалял наблюдателя раньше уведомления и мог оставить приватный экран после 401. Добавлена проверка истёкшей сессии из чата, повторены AUTH-сценарии.

## Предварительный контракт

Все пути начинаются с `/__preview/tracks/:id/tutor`. Адаптер блокирует их вне mock-режима. Хранилище — `sessionStorage` отдельно для каждой preview-личности; это не серверное хранение.

| Метод и суффикс | Запрос / ответ |
| --- | --- |
| GET `/` | Курс, доступные темы, contextVersion, threads с историей |
| POST `/threads` | `{ topicId: string \| null, contextVersion }`, `Idempotency-Key`; новый thread |
| POST `/threads/:thread/messages` | `{ text, contextVersion, clientMessageId }`, такой же `Idempotency-Key`; обновлённый thread |
| PUT `/threads/:thread/context` | `{ expectedVersion, contextVersion }`; обновлённый thread после подтверждения |

Сообщение: `id`, `clientMessageId`, `role`, `blocks`, `status`, `contextVersion`, `sources`. Текст, код, списки и таблицы используют структурированные блоки этапа 6. Backend должен подтвердить реальные DTO, пагинацию, модель версии контекста, дедупликацию и семантику восстановления.

Обработчики проверяют сессию и владельца курса; заблокированные темы отклоняются. Несовпадение версии или повтор ключа с другим содержимым возвращает 409. После задержки ответа повторно проверяется личность пользователя. Автоматических повторов мутации нет.

Режимы проверки: установить `sessionStorage['repeat-preview-tutor-response']` в `offline`, `lost` или `partial` перед отправкой. Режим одноразовый: отказ до сохранения, потеря ответа после сохранения, неполный ответ соответственно.

Актуальный remote backend по-прежнему не подтверждён: последний исследованный commit `de08e1d420239bc63bdded2355e29418e926c5f2` содержит gitlink без адреса `.gitmodules`. Исторический локальный `src/api/v1/tutor.py` имеет `/chat-threads`, отдельную установку контекста, отправку с HTTP 202 и историю с cursor. Наш предварительный синхронный ответ нельзя считать его готовым контрактом. Нового адреса API от пользователя пока нет. Backend-файлы не менялись.

При изменении высоты области история остаётся внизу только если пользователь уже был внизу.

Горизонтального переполнения нет; увеличенный текст требует вертикальной прокрутки. Снижение viewport имитирует ограниченную высоту, но не заменяет проверку реальной экранной клавиатуры iOS/Android.

## Открытые границы

- Реальные AI-ответы, источники, права и долговременное хранение требуют API.
- Потоковая выдача не реализована без согласованного протокола. Нет ложной анимации «печати» по токенам.
- Drawer поверх урока, вложения, архив/закрепление диалогов, source preview по точному фрагменту, настройки наставника и тренировочные карточки макета остаются отдельными задачами. Сейчас источники — безопасные ссылки под сообщением; контекст — курс/тема и версия программы.
- В mock-истории нет серверной пагинации; длинная история проверена, но бесконечный список не заявляется.
- Физическая клавиатура телефона, VoiceOver/NVDA и реальный API не проверены.
