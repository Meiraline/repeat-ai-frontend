# Статус реализации

Обновлено: 21.09.2026.

## Текущий результат

Продолжен этап 9: базовый тон, теплота, эмоциональность, заголовки/списки и эмодзи связаны с демонстрационными ответами и историей. [Отчёт](stage9-communication-style.md). Реальный AI и профильная синхронизация не подключены; быстрые ответы и расширенные правила остаются открытыми.

Продолжен этап 9: инициативность наставника — следующий вопрос, проверка понимания и практика — связана с демонстрационными ответами и снимками истории. [Отчёт](stage9-initiative.md). Открыты быстрые ответы, расширенный стиль, безопасность и приватность; реальный AI не подключён.

Продолжен этап 9: выбор персонажа наставника, формата помощи и подробности связан с чатом; исторические ответы сохраняют собственные настройки. [Отчёт](stage9-mentor.md). Реальный AI и синхронизация с профилем не подключены. Открыты инициативность, расширенный стиль общения, безопасность и приватность.

Продолжен этап 9: выбор акцентного цвета с предпросмотром, применением, отменой, сохранением на устройстве и независимым сбросом. [Отчёт](stage9-appearance.md). Тёмная тема, плотность, наставник, безопасность и приватность остаются открытыми.

Продолжен этап 9: доступность на устройстве — размер текста, уменьшение движения с приоритетом системных настроек, сохранение, отмена и сброс. Работает без нового API, включая production. [Отчёт](stage9-accessibility.md). Следующие открытые части: оформление, настройки наставника, безопасность и приватность; юридические тексты и реальные серверные контракты остаются внешними зависимостями.

Продолжен этап 9: публичный лендинг `/` с оригинальными иллюстрациями Figma, адаптивными секциями, тарифами, FAQ и предварительным рендерингом для SEO. [Отчёт лендинга](stage9-landing.md). Далее — расширенные настройки; выпуск зависит от реального API, юридических текстов, домена и проверки производительности.

Продолжен этап 9: тарифы и тестовый checkout, возврат, отключение/возобновление автопродления. Только mocks; реальные платежи заблокированы. [Отчёт billing](stage9-billing.md). Далее — расширенные настройки и лендинг; юридические документы ожидаются от владельца.

Начат этап 9: `/app/settings` — профиль, регион, форматы и напоминания; сохранение, конфликт версии, потерянный ответ, отмена правок и истечение сессии проверяются на mocks. Расширенные настройки, тарифы и лендинг остаются открытыми. [Отчёт первой части этапа 9](stage9-settings.md).

Этап 8: экзамен с четырьмя типами ответов, автосохранением и результатом, итоговый проект и заявка на диплом работают на mocks. Следующая тема открывается только через успешный результат mock API. Персональная выдача и файлы не подключены; скачивается явно обозначенный PNG-образец. [Отчёт этапа 8](stage8-assessments-diploma.md), [проверки](compatibility-matrix.md).

Актуализация backend: fetch 21.09.2026 вернул `de08e1d420239bc63bdded2355e29418e926c5f2`; вместо исходников в дереве находится gitlink без `.gitmodules`. Запрошен актуальный адрес backend или Swagger. Упоминания `12bfd8579…` ниже относятся к историческому снимку.

Выполнена доступная часть первого шага — этапа 0: создана структурная инвентаризация Figma, проверен первый экран авторизации и образец исходного изображения, просмотрена ветка бэкенда, принято решение о рендеринге индексируемого лендинга. Подтверждение серверных контрактов и доступность реальных устройств остаются открытыми.

Реализована основа этапа 1 в `frontend/`: React/TypeScript/Vite, React Router Framework Mode, prerender `/`, диагностический `/app`, 404, Query, HTTP-клиент, Zod, MSW, Storybook, ESLint с границами модулей и браузерные проверки. Экранные оболочки временные. Реальная интеграция API пока не подтверждена.

Завершён этап 2: 11 новых компонентов Atomic Design для AUTH, обновлён StatusPanel, перенесены необходимые иконки, токены и шрифты. Описание — [дизайн-система](design-system.md).

На этапе 3 реализована основная frontend-часть: AuthTemplate, AppShell, вход/регистрация/восстановление/подтверждение email, защищённые маршруты, выход с очисткой кеша, мобильное меню и 10 экранов онбординга с предварительным сохранением на mocks. `/app` теперь требует проверки сессии. Полный кабинет относится к этапу 4. [Запуск, сценарии и ограничения этапа 3](stage3-auth-onboarding.md).

Этап 3 **не подтверждён с реальным API**. Открыты повтор verification email, утверждённый контракт онбординга, юридические документы, аватар/варианты оформления и проверки физических устройств. 21.09.2026 повторный fetch backend показал тот же commit `12bfd8579e65799117187445bd8fca508af0c43b`.

Проект подключён к `origin=https://github.com/154ajax-collab/EGE.git`; локальная ветка `frontend` создана от `repeat-center`. Аккаунт GitHub `Meiraline` имеет только read-доступ (`permissions.push=false`): удалённая ветка не опубликована. Для push владельцу репозитория нужно предоставить этому аккаунту Write. Backend-файлы не менялись.

## Проверки этапа 1

- `npm run check`: typecheck, ESLint, Prettier, 12 unit-тестов HTTP/окружения и production build — успешно.
- `npm run build-storybook` — успешно. Предупреждение о размере служебного Storybook bundle не относится к клиентскому приложению.
- ESLint отклоняет пробный импорт HTTP-клиента из атома UI; пример передан через stdin, файл-заглушка не создавался.
- `react-router build --mode mock` намеренно завершается ошибкой до сборки: mocks в production запрещены.
- Chrome: 4 dev browser-теста на desktop/320 px и 1 production-тест прошли. Проверены переход, прямой `/app` и refresh, 404, skip-link с фокусом, отсутствие JS-ошибок, prerender и отсутствие MSW worker в production.
- Production smoke также прошёл в Chromium Headless Shell 153.0.8010.12. API в локальном preview возвращает явный 503; проверена ошибка с кнопкой повтора.
- Полный `npm run test:e2e`: 10/10 успешно в Chromium, Firefox, WebKit, WebKit 390 px и Chromium 320 px. После исправления порядка фокуса skip-link проверка Tab/Enter проходит во всех проектах. Версии и размеры — в [матрице](compatibility-matrix.md).
- Экран `/app` на 320×740 визуально просмотрен; горизонтальной прокрутки нет. Это проверка оболочки, не сверка законченного экрана с Figma.
- CI workflow подготовлен в `.github/workflows/frontend.yml`; на GitHub ещё не запускался из-за отсутствия права push.

Команды и правила хостинга: [frontend/README.md](../frontend/README.md). Реальная сессия, серверные сценарии и физические мобильные устройства этой проверкой не подтверждаются.
