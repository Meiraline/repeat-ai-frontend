## Использование

```tsx
import { TextField } from '@/components/molecules/TextField';
import { Button } from '@/components/atoms/Button';

<TextField
  label="Пароль"
  name="password"
  type="password"
  autoComplete="current-password"
  error={passwordError}
/>
<Button type="submit" loading={isSubmitting} fullWidth>
  Войти
</Button>
```

- Для обычного поля формы использовать TextField: он связывает label, hint и error через ID и ARIA. Input — нижний уровень без сообщения об ошибке.
- У Button по умолчанию `type="button"`. Отправку формы указывать явно. `loading` блокирует повторное нажатие и сообщает состояние.
- Icon без `label` декоративный. Для самостоятельной кнопки с иконкой использовать IconButton с обязательным `label`.
- Checkbox должен иметь доступное имя через label/ARIA. Для согласия использовать ConsentRow; переход по юридической ссылке не меняет отметку.
- Ссылки остаются ссылками, действия — кнопками. В готовых экранах подставлять реальные маршруты и согласованные юридические документы.
- Добавлять варианты через props и семантические токены, не копировать CSS компонента в страницу. Не импортировать molecules из atoms или API из UI.

## Адаптация и отличия от статичного макета

- Размеры Input: 52/60 px; Button: 44/48 px и AUTH 52 px при базовом размере шрифта. Размеры в rem растут вместе с текстом.
- У иконок-кнопок и checkbox область нажатия не меньше 44 px. Отдельная ссылка восстановления также имеет увеличенную область; это меняет вертикальный размер демонстрационной формы.
- Кнопка раскрытия пароля закреплена справа. При ширине поля менее 18 rem декоративная левая иконка скрывается, освобождая место для ввода; подпись и действия сохраняются.
- Длинные label, ошибки, подписи и кнопки переносятся. Согласие не ограничено фиксированной высотой. Фокус клавиатуры видим, значение пароля не теряется при раскрытии.
- Экспорт CSS градиента содержал дублирующую стоп-точку с резкой полосой; градиент нормализован по изображению Figma до плавного перехода.
- Текст ошибки затемнён относительно розового контура; danger использует тёмный текст. Полная проверка контрастности всех будущих экранов остаётся частью подготовки к выпуску.
- Spinner вращается 1 секунду, linear; это решение реализации, не подтверждённая длительность прототипа. При `prefers-reduced-motion` вращение отключено.
- Ошибки сообщаются рядом с полем, загрузка — через status. Диалоги и меню добавляются при первом сценарии, которому они нужны; универсальные заготовки сейчас не создаются.

## Проверка

Команды из `frontend/`: `npm run check`, `npm run build-storybook`, `npm run test:storybook`, `npm run test:e2e`, `npm run test:e2e:production`.

Storybook запускается через `npm run storybook`, адрес http://127.0.0.1:6006/?path=/story/design-system-auth-foundations--auth-composition. Перед браузерными тестами Storybook его ручной dev-сервер нужно остановить: тесты поднимают отдельный экземпляр на том же порту.

Браузерные проверки охватывают клавиатуру, показ пароля, связанные ошибки, согласие и ссылки, disabled/loading, длинные подписи, 200% размер текста и reduced motion. Это не проверка физических iPhone/Android и не полный аудит доступности.

Визуально просмотрены [desktop](qa/stage2-auth-desktop.png), [320 px](qa/stage2-auth-320.png), [320 px с текстом 200%](qa/stage2-auth-320-text200.png). На узком экране горизонтальной прокрутки нет. Результаты прогонов — в [статусе](implementation-status.md) и [матрице](compatibility-matrix.md).
