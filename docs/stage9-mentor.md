## Связь с чатом

Выбор меняет имя и карточку наставника в боковой панели чата. Каждое новое сообщение отправляется со снимком `preferences: { persona, help, detail }`. Ответ хранит тот же снимок; старые сообщения отображаются с прежним персонажем. Для старых записей без снимка используются исторические значения: Лира, подсказка, баланс.

Preview-обработчик показывает различия формата и длины в явно обозначенном шаблонном ответе. Это не реальная генерация и не реализация характера персонажа. Production guard реального репетитора сохранён. Формат «Решение» сам по себе не предоставляет доступ к ответам экзаменов.

Повтор после потерянного ответа использует прежние параметры, ключ и текст. Восстановление частичного ответа берёт параметры из сохранённого пользовательского сообщения, даже после перезагрузки и смены настроек. Повтор ключа с другими параметрами должен возвращать 409.

## Хранение и архитектура

- `features/tutor/model/preferences.schema.ts` — типы и валидация; провайдер в том же модуле хранит настройки устройства.
- `components/organisms/MentorSettingsFields` — управляемые поля без API и хранилища; `pages/settings/MentorSection` соединяет их с моделью.
- `assets/mentors/catalog.ts` — ссылки на существующие оригинальные PNG из экспорта этапа 3. Изображения не перерисованы и не перекодированы.
- `TutorMessage` получает имя и изображение через props; не читает настройки самостоятельно.

Значения находятся в `localStorage['repeat-device-mentor-v1']`, действуют для браузера после выхода из аккаунта и синхронизируются между его вкладками. На другие устройства не переносятся. При запрете записи выбор применяется до перезагрузки, ошибка постоянного сохранения показывается явно. Повреждённые значения заменяются стандартными. Настройки из исторического онбординга пока не объединены с этим локальным выбором; синхронизация с профилем требует контракта backend.

## Адаптация и границы

Вместо полного отдельного экрана макета используется карточка в текущих настройках. Все четыре персонажа показаны доступными радиокарточками; модальное раскрытие профиля не реализовано. На узком экране карточки складываются в одну колонку. Формат и подробность используют подписанные нативные списки. Стиль общения, инициативность, языки, аналогии и переопределения конкретного курса остаются открытыми; недействующие переключатели не добавлены.
