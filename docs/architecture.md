# Архитектурные решения

Дата: 20.09.2026. Архитектура папок сохраняет Atomic Design и функциональные модули из [правил](../ии-хелперы/ПРАВИЛА-РАЗРАБОТКИ.md).

## ADR-001. Индексируемый лендинг и клиентский кабинет

Пользователь подтвердил: публичный лендинг должен индексироваться поисковиками.

Выбран подход: React + TypeScript + Vite, React Router в Framework Mode; публичный лендинг предварительно рендерится при сборке, кабинет работает как SPA с отдельным backend API. React Router позволяет сочетать `ssr: false` и выбранные prerender-маршруты, без обязательного сервера рендеринга при каждом запросе. [Документация React Router](https://reactrouter.com/how-to/pre-rendering)

На этапе основы проверить эту комбинацию на минимальном маршруте. Предварительно рендерить `/`; юридические страницы добавлять после получения окончательного содержимого. Не делать общий `prerender: true` для всех статических путей: auth и кабинет не должны получать приватные данные при сборке.

Следствие для структуры: `src/app/root.tsx` — документ и провайдеры, `src/app/routes.ts` — декларация маршрутов, при необходимости `src/app/router` — route adapters. Основной экран остаётся в `src/pages`, компоненты и функциональные модули сохраняют свои места. Настроить `appDirectory` на `src/app`. `main.tsx` и второй самостоятельный BrowserRouter не нужны; точку входа предоставляет framework, при необходимости настраивается `entry.client.tsx`.

Browser-only код не должен обращаться к `window` на этапе импорта или build-time render. MSW включается только на клиенте в явно заданном dev-режиме. Реальную сессию и пользовательские данные загружать на клиенте. Общий layout должен допускать безопасный рендеринг при сборке. [React Router: SPA](https://reactrouter.com/how-to/spa)

Критерии этапа основы: production HTML для `/` содержит заголовок и содержимое тестовой страницы; кабинет открывается по прямому URL через корректный SPA fallback; сборка не запрашивает приватный API.

Критерии готового лендинга: title, description, canonical после выбора домена, Open Graph, индексируемые ссылки; sitemap содержит только публичные страницы. Auth/кабинет имеют noindex, но защиту данных обеспечивает серверная авторизация, а не robots.txt. При прямом запросе публичного URL отдаётся его HTML, а не пустой SPA shell. Согласовать домен, хостинг и правила 404 перед публикацией. Подготовка HTML не гарантирует фактическое включение страницы в поисковый индекс.

## ADR-002. Основа интеграции

Источник фактических деклараций API — ветка `repeat-center` репозитория `154ajax-collab/EGE`. Проверенный commit и ограничения записаны в [api-contract.md](api-contract.md). DRAFT используется как описание намерений, когда реализация отсутствует, но не подменяет существующие пути API.

Репозиторий бэкенда просмотрен в отдельной временной копии. В него не вносились изменения, сервис и база не запускались. До исправления синтаксиса и получения тестового адреса frontend разрабатывается на явно обозначенных mocks.

## ADR-003. Статические assets

Источник — точные файлы и узлы Figma. Оригиналы скачиваются без пересжатия. Проектные оптимизированные варианты создаются отдельно, только после визуальной сверки. Пробный исходник и его размер зафиксированы в [карте Figma](figma-map.md).

## ADR-004. Общий репозиторий и границы frontend

По поручению пользователя рабочая папка подключена к `https://github.com/154ajax-collab/EGE.git`. Локальная ветка `frontend` основана на `origin/repeat-center`, commit `12bfd8579e65799117187445bd8fca508af0c43b`. Backend уже использует корневой `src/`, поэтому приложение находится в `frontend/`, со своим package.json и npm lock. Все frontend-пути `src/...` в документации и реестрах Figma подразумевают `frontend/src/...`; общие документы остаются в корне. Backend-код не меняется.

Atomic Design создаётся по мере появления компонентов. ESLint проверяет направления shared/features/components, запрет обхода публичного интерфейса features и импортов mocks из production-модулей. Первые PageFrame и StatusPanel — проверка инфраструктуры, не окончательное воспроизведение экранов Figma.

Сборка ADR-001 проверена: `build/client/index.html` содержит лендинг до выполнения JS, а `__spa-fallback.html` используется для кабинета. Локальные правила хостинга и запуск описаны в [README frontend](../frontend/README.md). Сам факт prerender не означает завершения SEO и публикации лендинга.
