# Этап 4: кабинет и создание учебного плана

Дата: 21.09.2026. Ветка: `frontend`. Основной frontend-сценарий реализован с MSW; реальная интеграция генерации остаётся заблокированной.

## Что работает

- `/app` и `/app/courses`: пустое состояние, карточки активных/завершённых курсов, фильтр в URL, сводные показатели, календарь и список дедлайнов. Черновики отображаются отдельно от учебных треков.
- `/app/plans/new`: введение и создание черновика явным действием.
- `/app/plans/:id`: семь вопросов интервью, история ответов, сохранение, проверка срока, принятие риска, сводка и запуск генерации.
- Генерация: queued/running/succeeded/partial/failed, пять этапов, задержка, частичный черновик и явный повтор после ошибки. Опрос прекращается после финального статуса, ошибки запроса и ухода со страницы. При возвращении запрашивается состояние задания.
- Сохранение использует версию; конфликт не очищает текущий ответ. Несохранённый ввод защищён диалогом при переходе и предупреждением браузера при закрытии/перезагрузке.
- При потере ответа запуска повтор отправляется с прежним ключом. Новый ключ используется только для явного повторного запуска завершившегося с ошибкой/частичным результатом задания.

Созданный план **не становится активным курсом**. Полный просмотр, согласование, утверждение и изменение программы относятся к этапу 5, учебный проигрыватель — к этапу 6. Кнопка «Программа» существующей карточки пока открывает доступную сводку, явно обозначая этот предел.

## Запуск

Из `frontend/`: `npm run dev:mock`. Открыть http://127.0.0.1:3000/auth/login, войти `student@example.test` / `Repeat123`. Нажать «Создать первый курс» → «Начать интервью».

1. Ответить на вопросы. «Продолжить» сохраняет ответ, «Сохранить и выйти» сохраняет текущий ввод без перехода к следующему вопросу. Возврат к черновику доступен из кабинета.
2. В демонстрационной оценке срок меньше 84 дней либо нагрузка меньше 5 ч/нед. показывает риск. Это условие находится только в mock handler и **не является настоящей AI-оценкой**.
3. Подтвердить риск либо изменить параметры, проверить сводку и нажать «Составить программу».
4. Обновить страницу во время генерации. Через примерно 7 секунд тестовое задание завершится и покажет демонстрационную структуру из трёх тем.

Данные имитируемого сервера живут в `sessionStorage` вкладки, отдельно для каждого тестового email. Они переживают reload, но не заменяют серверное хранение и не гарантируют сохранность после закрытия вкладки. Не вводить реальные личные данные. Ответы не отправляются во внешнюю AI-систему.

### Сценарии для QA

В консоли браузера, только при `dev:mock`:

```js
// Карточки из Figma; затем обновить кабинет.
sessionStorage.setItem('repeat-preview-dashboard', 'sample');
// Убрать примеры карточек:
sessionStorage.removeItem('repeat-preview-dashboard');

// Перед запуском генерации: success / partial / failed / slow.
sessionStorage.setItem('repeat-preview-generation', 'partial');
// Сымитировать потерю первого ответа уже запущенного задания:
sessionStorage.setItem('repeat-preview-start-response', 'lost');
```

`slow` длится около 65 секунд, предупреждение о задержке появляется после 15 секунд. Mock вычисляет статус по времени запуска при запросе; настоящего фонового процесса в браузере нет. Примеры курсов нужны для просмотра карточек и не возникают от генерации неутверждённого плана.

## Контракты и структура

Реальный `GET /dashboard?filter=active|attention|completed` использует проекцию полей текущего backend: summary, tracks, currentTopic, nextAction, nextDeadline, riskStatus, partialErrors. Статус фактической интеграции не подтверждён. В исходном backend фильтр attention ещё не отбирает только проблемные карточки; это нужно исправить на сервере.

Предварительный контракт планов полностью изолирован:

| Запрос | Назначение |
| --- | --- |
| GET `/__preview/plans` | Список собственных черновиков |
| POST `/__preview/plans`, `Idempotency-Key` | Создание черновика |
| GET `/__preview/plans/:id` | Восстановление ответов и текущего шага |
| PUT `/__preview/plans/:id`, `If-Match` | Сохранение черновика и проверка версии |
| POST `/__preview/plans/:id/jobs`, `Idempotency-Key` | Идемпотентный старт задания |
| GET `/__preview/jobs/:id` | Фактический статус имитируемого задания |
| POST `/__preview/plans/:id/retry`, новый `Idempotency-Key` | Новая попытка после partial/failed |

`features/plans` блокирует эти запросы вне mock-режима. Подмена настоящего API на fixtures при ошибке отсутствует. Реальные `/plan-interviews` не подключены к выдуманному опросу `/jobs`.

UI: `ProgressBar` — атом; `CourseCard`, `PlanIllustration` — молекулы; `InterviewForm`, `DeadlineCalendar` — организмы; `AppShell` — шаблон. `pages/workspace/Workspace` соединяет навигацию и выход с функциональным модулем сессии. `features/plans` содержит схемы, адаптеры и запросы; тестовые данные и расчёт статуса — только в `mocks`.

## Figma и адаптация

Изучены design context и скриншоты: `5292:15469`, `5292:15869`, `5355:20457`, `5355:20796`, `5355:21151`, `5355:21481`, `5355:21842`. Использованы оригинальные PNG, экспортированные иконки и CSS-кадрирование исходного атласа. [Реестр с SHA-256](figma/stage4-assets.json). Одинаковые байты атласа используются одним файлом. Figma не изменялась.

Desktop: боковая навигация 212 px, содержимое на Grid, правая колонка с календарём/иллюстрацией. На узких экранах меню открывается диалогом, колонки перестраиваются, кнопки и длинные подписи переносятся. Состояние формы не привязано к ширине окна.

Осознанные отличия: 44 px области управления, увеличенный читаемый текст карточек, естественная высота контента, явное сохранение вместо неподтверждённого autosave, календарь показывает даты ответа API и текущий месяц вместо статичного апреля 2025. Поиска в выбранном макете нет — реализованы три заданных фильтра. Архив, меню управления курсом, кредиты и уведомления о готовности ожидают своих сценариев/контрактов. Некоторые маленькие иконки экспортированы в масштабе 1×; их качество на плотных дисплеях ещё требует проверки.
