# Этап 3: оболочка, авторизация и первый запуск

Дата: 21.09.2026. Рабочая ветка: `frontend`. Реализован frontend сценариев на MSW. Реальный API не проверен: `git fetch origin repeat-center` по-прежнему возвращает commit `12bfd8579e65799117187445bd8fca508af0c43b` с ранее описанными блокировками.

## Запуск и проверка вручную

Из `frontend/`: `npm run dev:mock`, затем http://127.0.0.1:3000/auth/login.

- Демо-вход: `student@example.test` / `Repeat123`. Использовать только вымышленные данные. Жёлтая полоса явно обозначает тестовый режим.
- Прямая ссылка `/app/courses` сначала открывает вход, после входа возвращает в кабинет. Обновление страницы повторно проверяет профиль.
- Для нового аккаунта пройти `/auth/register`, затем открыть в той же вкладке `/auth/verify?token=preview-verify` и подтвердить адрес кнопкой. Письмо не отправляется. Ссылка одноразовая в рамках тестовой вкладки.
- После подтверждения войти с зарегистрированными данными: откроется `/onboarding`. Настройки сохраняются при переходе между шагами; можно вернуться назад, обновить страницу или пропустить знакомство.
- Для проверки сброса сначала запросить восстановление на email демо-аккаунта или зарегистрированного пользователя, затем открыть `/auth/reset?token=preview-reset` в той же вкладке. После успешного сброса использовать новый пароль.
- Для истечения сессии удалить `repeat-preview-session` из sessionStorage и обновить приватную страницу. Это тестовая имитация, не способ управления реальными сессиями.
- Открыть «Меню» на телефоне, закрыть Escape: фокус возвращается на кнопку. Выход очищает Query cache; при ошибке выхода интерфейс не заявляет, что серверная сессия завершена.

Mocks хранят одну новую тестовую учётную запись и её хеш пароля в sessionStorage вкладки; настоящие пароли туда вводить нельзя. Mock-сессия — флаг, а не HttpOnly cookie. Закрытие вкладки сбрасывает сценарий. Это не сервер, не проверка безопасности авторизации и не синхронизация между устройствами.

## Маршруты

| URL | Результат |
| --- | --- |
| `/auth/login` | Вход, ошибки полей/сервера, безопасный `returnTo` |
| `/auth/register` | Имя, email, пароль, согласие; ожидание подтверждения |
| `/auth/restore` | Одинаковое сообщение для любого email, диалог, задержка повторной отправки |
| `/auth/reset?token=…` | Новый пароль, повтор, проверка совпадения |
| `/auth/verify?token=…` | Подтверждение email явным действием |
| `/auth/verified`, `/auth/reset-done`, `/auth/invalid` | Результаты операций; сами по себе не предоставляют доступ к данным |
| `/app`, `/app/courses` | Защищённая оболочка, текущий диагностический список обучения |
| `/onboarding` | Профиль → знакомство → 7 тематических шагов → итог |
| `/legal/terms`, `/legal/privacy` | Явное сообщение об отсутствии утверждённых документов |

Auth и приватные страницы имеют noindex. Публичный `/` остаётся prerendered. Preview-сервер расширен для прямых URL; те же правила нужны на реальном хостинге.

## Архитектура

- `features/auth`: схемы ввода, API-адаптеры, запрос профиля, очистка сессии и кеша. Пароли не сохраняются production-кодом. CSRF возвращается в память; имя заголовка и восстановление токена после reload ожидают контракта.
- `app/router/ProtectedLayout`: проверка сессии до вывода приватного содержимого. HTTP 401 приватного Query переводит сессию в anonymous; временная ошибка сети показывает повтор, а не ложный выход.
- `components/templates/AuthTemplate`, `AppShell`: компоновка без запросов; `organisms/auth/AuthForm`, `OnboardingForm`: UI и callbacks.
- `molecules/Dialog`: нативный modal dialog, Escape, фон недоступен, возврат фокуса. `ChoiceGroup`: нативные radio/checkbox, клавиатура и перенос подписей.
- `pages/auth`: соединение форм, валидации и API; `pages/onboarding`: шаги, сохранение и состояние отправки.
- `features/onboarding`: отдельный предварительный контракт `GET/PUT /__preview/onboarding`. Запросы разрешены только при `env.enableMocks`; production показывает недоступность настройки и ссылку в кабинет.
- В production нет автоматического fallback на fixtures. Подключение настоящего API остаётся через общий HTTP-клиент и cookie credentials.

`returnTo` допускает только реализованные внутренние приватные пути. Query cache отменяется и очищается при смене аккаунта/выходе. Ссылка восстановления удаляется из адресной строки после чтения; токен хранится только в памяти экрана. После перезагрузки нужно повторно открыть ссылку из письма. Подтверждение email не запускается автоматически при загрузке страницы и не обещает автологин.

## Незакрытые зависимости

| Область | Ограничение |
| --- | --- |
| Реальная авторизация | Backend не запускается из-за ранее найденного синтаксиса; нет тестового URL, подтверждённого CSRF flow и runtime проверки cookie |
| Повтор verification email | Endpoint отсутствует. Кнопка реальной повторной отправки не выдумана; восстановление пароля имеет свой работающий на mocks cooldown |
| Юридические документы | Утверждённые тексты и версии не предоставлены. Production-регистрация блокируется без версий; ссылки сейчас явно сообщают об отсутствии документов. Перед включением регистрации нужны и тексты, и версии |
| Сохранение онбординга | Предварительный mock-контракт, не утверждённый backend API. Не подменён существующим PATCH профиля |
| Аватар и оформление | Загрузка аватара не реализована без контракта; доступны светлая тема, синий акцент и стандартная плотность. Остальные варианты оформления показаны недоступными |
| Учебные предпочтения | Сохраняются на mocks; их применение к курсам, AI и экзаменам проверяется вместе с соответствующими сценариями следующих этапов |
| Физические устройства | Автозаполнение менеджером паролей, экранная клавиатура iOS/Android и настоящие cookies Safari ещё требуют устройств |

Не считать этап подтверждённым с настоящим API или готовым к выпуску. Доступная frontend-часть позволяет продолжать этап 4 независимо от этих серверных зависимостей.
