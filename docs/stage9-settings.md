# Этап 9 — первая часть: профиль

Дополнение: [настройки доступности на устройстве](stage9-accessibility.md) реализованы отдельным блоком; сохранение профиля не изменено. Тарифы и лендинг также уже реализованы в демонстрационном объёме, см. текущий статус проекта.

Дата: 21.09.2026. Маршрут: `/app/settings`, защищён проверкой сессии.

## Реализовано

- Имя, имя для будущего диплома, часовой пояс IANA, предпочитаемые форматы и еженедельное напоминание.
- Сохранение через `PATCH /me/profile` с исходной версией в `If-Match`; в тело не попадают `version` и неизменяемый `language`.
- Состояния сохранения, отмены правок, ошибки, конфликта версии и завершённой сессии. При ошибке черновик остаётся в форме. Перед повторной записью нужно явно загрузить актуальный профиль, заменив черновик: это также позволяет проверить результат потерянного ответа.
- После подтверждения обновляется общий кеш профиля и имя в оболочке. Отмена запроса при уходе со страницы предотвращает позднее обновление кеша.
- Доступные поля вынесены в organism `ProfileSettingsFields`, собранный из существующих Input/Checkbox; страница связывает форму, API и сессию. Модель и сохранение профиля остаются в существующем `features/auth`, владеющем профилем сессии.

## Figma и адаптация

Получены design context и изображение `5292:16134` (SCR-SETTINGS-001), страница «Прототип Десктоп MVP», файл `hvF90E8EGKFYvS1FxAgSvQ`. Используются существующие токены, оболочка, кнопки и оригинальные иконки; новые растровые исходники не нужны.

Это частичная реализация макета: карточки профиля/региона и локальная навигация адаптированы под доступные поля API. Расширенные категории, аватар, тема, акцент, плотность, настройки наставника, безопасность и удаление пока не реализованы. Рабочая форма не показывает фиктивно сохраняемые переключатели. Настройки форматов и напоминаний объединены в одну секцию; они не меняют существующие курсы и в preview не отправляют письма.

На узком экране навигация и карточки выстраиваются последовательно, действия переносятся. Поддерживаются клавиатура, подписи полей, live-статус и увеличение текста браузером. QA-снимки: `docs/qa/stage9-settings-*`.

## API и проверка

Контракт соответствует историческому backend-снимку: `src/api/v1/profile.py`, `src/schemas/profile.py`. Совместимость с текущим живым сервером пока не подтверждена. В preview MSW проверяет входные поля, версию и сессию, хранит данные в `sessionStorage`.

Для проверки потерянного ответа: `sessionStorage['repeat-preview-profile-response'] = 'lost'`. Следующая запись сохраняется в mock, но ответ теряется. Кнопка загрузки получает актуальные данные без повторной записи. Этот переключатель отсутствует в production.

Этап 9 остаётся открытым: далее расширенные настройки, тарифы/подписка и публичный лендинг. Утверждённые юридические тексты и актуальный API оплаты пока не получены. Checkout нельзя подтверждать по параметрам URL.
