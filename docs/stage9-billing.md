# Этап 9 — тарифы и тестовый сценарий подписки

21.09.2026. Маршруты `/app/billing`, `/app/billing/checkout`, `/app/billing/return` защищены проверкой сессии.

## Реализовано

- Три карточки тарифов из Figma. Цены 0/990/2490 ₽ и лимиты находятся в mock-конфигурации, а не в UI. Они обозначены как демонстрационные и не являются действующим предложением.
- Создание тестовой оплаты → ожидание → подтверждение, отказ или отмена. Кнопки симуляции явно подписаны; данные карт не запрашиваются, денег и реальных подписок нет.
- Возврат сверяет идентификатор операции с данными аккаунта. `success`, `status` и другие параметры URL не меняют подписку. Неизвестная операция показывает ошибку.
- Отключение автопродления с подтверждением, сохранение доступа до конца периода, возобновление подписки до его окончания.
- Mock-сервер завершает отменённую подписку при следующем GET после окончания периода. Повторное оформление не предоставляет второй trial.
- Потерянный ответ блокирует повторные действия до проверки состояния. Незавершённая оплата доступна после обновления страницы.
- Сессия 401 очищает приватный кеш; запросы отменяются при уходе. Тестовое хранилище разделено по идентификатору аккаунта.

## Временный контракт

Все запросы ниже ограничены режимом mocks. В production адаптер возвращает `BILLING_UNAVAILABLE` до сетевого запроса. Требуется согласованный серверный контракт, простой замены base URL недостаточно.

| Запрос | Назначение |
| --- | --- |
| `GET /__preview/billing` | Каталог, версия, подписка, лимиты и последняя операция |
| `POST /__preview/billing/checkout` | Создать/восстановить ожидание, `Idempotency-Key` |
| `POST /__preview/billing/checkout/:id/simulate` | Только preview: подтвердить, отклонить или отменить операцию |
| `PUT /__preview/billing/subscription` | Установить `autoRenew`, `If-Match` версии |

Checkout: `processing / succeeded / failed / cancelled`. Подписка: `free / trialing / active / cancel_at_period_end`. UI отображает ответы, не рассчитывает право на доступ по имени тарифа. Само ограничение доступа учебных модулей пока не подключено.

Повторный запрос с тем же ключом или при существующей processing-операции не создаёт новую оплату. Повторное подтверждение не продлевает период. Mock хранит только последнюю операцию: это не реализация полноценного журнала платежей.

Для QA: `sessionStorage['repeat-preview-billing-response'] = 'lost'` теряет следующий ответ после успешной записи. Хранилище: `repeat-preview-billing:<identity>`. Изменение `periodEnd` в тестовой фикстуре позволяет проверить окончание отменённого периода; в production этого механизма нет.

## Figma и структура

Использованы design context и изображения `6665:14919` (тарифы), `6665:15010` (оформление), `6665:15101` (подключение), `6665:15283` (управление). Файл `hvF90E8EGKFYvS1FxAgSvQ`, страница «Прототип Десктоп MVP».

`PricingCard` — molecule с историями Storybook; `features/billing` — схема, API и функциональный хук; `pages/billing` собирает маршруты в существующей оболочке. Используются существующие токены и assets оболочки. Новые изображения не понадобились.

Адаптивная сетка складывает карточки в одну колонку по доступной ширине. На телефоне сохраняются цены, условия, ошибки и действия. Реализация объединяет тарифы и текущую подписку; банковские поля заменены явно обозначенной симуляцией. Полное совпадение всех экранов Figma не заявляется.

## Открытые задачи

Реальный checkout/hosted fields, webhook-подтверждение, согласие с утверждёнными условиями, маска карты, замена способа оплаты, чеки и история, past_due/grace period, ошибки продления, журнал расхода, entitlements и реальный биллинг не подключены. Даты берутся из mock-ответа; его условные 30 дней платного периода не определяют календарные правила реальной подписки.

Этап 9 не завершён целиком: остаются расширенные настройки, публичный лендинг и предоставленные владельцем юридические документы. Результаты проверок — в `compatibility-matrix.md`.
